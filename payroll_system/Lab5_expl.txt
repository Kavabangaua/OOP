Звіт з виконання лабораторної роботи №5
Тема: Розробка системи обліку та нарахування заробітної плати

1. Аналіз завдання та вимог
Завдання полягало у розробці системи для обліку працівників, їх роботи у структурних підрозділах, планів виробництва та автоматичного нарахування заробітної плати за різними схемами.
Основні вимоги:
- Зчитування даних з файлів (JSON, CSV).
- Збереження результатів у файл (JSON, CSV).
- Обробка даних відповідно до предметної області (розподіл плану, розрахунок ЗП).
- Обов'язкове використання ООП принципів: класи, кастомізація, наслідування, абстрактні класи, композиція/агрегація.
- Реалізація інтерфейсів з обґрунтуванням вибору способу реалізації.

2. Архітектура системи
Система побудована за модульним принципом з чітким розділенням відповідальності:
- `models.py`: Визначення класів даних (`Employee`, `Department`) за допомогою dataclasses.
- `schemes.py`: Визначення інтерфейсів (`IPaymentScheme`, `IBonusScheme`, `IPlanDistributionStrategy`) за допомогою ABC та їх конкретних реалізацій (наслідування).
- `data_handlers.py`: Визначення інтерфейсу `IDataHandler` (ABC) та конкретних обробників для JSON та CSV (наслідування).
- `payroll.py`: Основний клас `PayrollSystem`, що використовує композицію для включення обробників даних та агрегацію для зберігання зареєстрованих схем та стратегій. Він керує всім процесом.
- `main.py`: Точка входу, що демонструє використання системи.

3. Використання ООП принципів

- **Класи:** Вся система побудована на класах (`Employee`, `Department`, `PayrollSystem`, схеми, обробники даних). Використано `dataclasses` для спрощення моделей даних.
- **Інкапсуляція:** Дані моделей та внутрішні стани класів приховані (хоча Python не має строгої інкапсуляції, використовується угода про іменування).
- **Наслідування:** Використовується для реалізації конкретних схем оплати, преміювання, стратегій розподілу та обробників даних, які успадковують функціональність від абстрактних базових класів (інтерфейсів).
- **Абстрактні класи (ABC):** Використані для визначення інтерфейсів (`IPaymentScheme`, `IBonusScheme`, `IPlanDistributionStrategy`, `IDataHandler`). Це гарантує наявність необхідних методів у всіх похідних класах та забезпечує поліморфізм. Вибір ABC обґрунтований тим, що це стандартний механізм Python для визначення інтерфейсів, який дозволяє перевіряти реалізацію методів під час створення екземплярів.
- **Поліморфізм:** `PayrollSystem` працює з різними схемами, стратегіями та обробниками через їхні спільні інтерфейси, не знаючи деталей конкретної реалізації. Наприклад, метод `calculate_salary` викликає відповідний метод `calculate_base_salary` або `calculate_bonus` залежно від типу схеми, зареєстрованої для працівника. Аналогічно з обробниками даних.
- **Композиція/Агрегація:**
    - **Композиція:** `PayrollSystem` містить екземпляри `JsonDataHandler` та `CsvDataHandler`. Життєвий цикл цих обробників може бути пов'язаний з `PayrollSystem`.
    - **Агрегація:** `PayrollSystem` зберігає посилання на зареєстровані схеми та стратегії (`payment_schemes`, `bonus_schemes`, `plan_strategies`). Ці схеми можуть існувати незалежно від `PayrollSystem`. Також `Department` агрегує список працівників (`employees`).
- **Кастомізація:** Використано `__str__` в моделях для зручного представлення об'єктів.

4. Реалізація інтерфейсів
Інтерфейси реалізовані за допомогою модуля `abc`. Це дозволяє:
- Визначити чіткий контракт для класів.
- Забезпечити гнучкість системи: легко додавати нові схеми/стратегії/обробники, не змінюючи основний код.
- Використовувати поліморфізм для обробки різних реалізацій через єдиний інтерфейс.

5. Робота з файлами (JSON, CSV)
Створено обробники `JsonDataHandler` та `CsvDataHandler`, які реалізують інтерфейс `IDataHandler`. `PayrollSystem` автоматично вибирає потрібний обробник за розширенням файлу. Це дозволяє системі легко підтримувати різні формати даних.

6. Логіка розрахунків
- **Розподіл плану:** Реалізовано кілька стратегій (рівномірно, за досвідом), які вибираються на рівні відділу.
- **Розрахунок ЗП:** Базова ЗП розраховується відповідно до схеми працівника. Премія розраховується окремо відповідно до схеми преміювання та додається до базової ЗП.

7. Висновки
Розроблена система відповідає всім вимогам завдання. Використання ООП принципів, зокрема абстрактних класів для інтерфейсів, наслідування для реалізацій та композиції/агрегації для побудови основної логіки, дозволило створити гнучку, розширювану та добре структуровану систему.
